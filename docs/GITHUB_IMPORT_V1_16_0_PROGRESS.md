# VoxLyra v1.16.0 — GitHub Import progress

Обновлено: 2026-08-12.

## Цель

Добавить GitHub только как дополнительный источник контента. После импорта книги и комиксы проходят существующий импортёр VoxLyra, сохраняются в существующее хранилище и БД и дальше работают как обычный контент. Перенос БД/библиотеки и отдельное GitHub-хранилище не создаются.

## Источник

По умолчанию: `Treninem/bookvoxlyra`, ветка `main`. Репозиторий, ветка и корневой путь задаются env. Токен хранится только в env и не выводится в интерфейс/историю.

## Реализовано в feature/github-owner-import

- отдельный непередаваемый `SYSTEM_OWNER_ID` для GitHub-импорта;
- серверная проверка владельца в сервисе и Telegram callbacks;
- скрытый раздел владельца `Контент → Импорт → GitHub`;
- проверка доступности репозитория;
- обнаружение пакетов и пагинация;
- manifest: package_id, content_type, title, language, version, files, checksums, created_at;
- SHA-256 проверка файлов;
- потоковое скачивание отдельных файлов пакета без clone репозитория;
- лимит размера пакета и проверка свободного диска;
- временная директория с гарантированной очисткой;
- импорт книги/комикса через существующий `import_library_zip`;
- журнал импорта с package_id, версией, commit SHA, статусом, размером, количеством файлов, VoxLyra ID и ошибкой;
- идемпотентность по успешно импортированному package_id/version/commit;
- обнаружение новой версии без автоматической перезаписи;
- явное действие владельца для обновления;
- массовый импорт всех новых книг и комиксов;
- массовое аудио временно пропускается по решению владельца;
- ошибка одного пакета не останавливает остальные;
- повтор неудачных импортов;
- экраны истории и ошибок;
- тесты owner/non-owner, manifest/SHA/path validation и bulk behavior;
- минимизирован diff `bot.py`/`config.py`: существующие комментарии и логика сохранены.

## Обязательный остаток перед merge

- усилить дедупликацию: внутренний ID, title+author, ISBN/идентификаторы, SHA исходника;
- проверить безопасное обновление существующего произведения с сохранением покупок, прогресса, отзывов, рейтингов и закладок;
- проверить rollback при ошибке существующего импортёра и отсутствие полупустых записей;
- тесты: missing file, download interruption, low disk, rollback, temp cleanup, version update и сохранение пользовательских связей;
- полный регрессионный аудит PR относительно `main`;
- выполнить тесты в окружении с зависимостями проекта;
- устранить причину `mergeable: false` до снятия draft.

## Текущее правило релиза

В `main` изменения не сливаются, пока обязательный остаток выше не закрыт и не проверен. README/этот статус обновляются при каждом следующем рабочем проходе.
