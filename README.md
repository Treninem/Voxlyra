# VoxLyra

VoxLyra — единая платформа для книг, комиксов/манги/манхвы/вебтунов и аудиокниг с Telegram-ботом, Telegram Mini App, VK Mini App, публикацией, модерацией и общей библиотекой.

## Текущая разработка — v1.16.0

Ветка: `feature/github-owner-import`.

Главная задача текущего обновления — защищённый импорт контента из GitHub. GitHub используется **только как источник**. После проверки пакет передаётся существующему импортёру VoxLyra и дальше использует существующие БД, хранилище, читалку, публикацию и пользовательские связи.

Источник по умолчанию: `Treninem/bookvoxlyra`. Репозиторий, ветка и корневой путь настраиваются через env.

### Уже реализовано

- отдельное непередаваемое право `SYSTEM_OWNER_ID`;
- скрытый раздел владельца `Контент → Импорт → GitHub`;
- серверный запрет GitHub-импорта для всех остальных пользователей;
- проверка репозитория и поиск пакетов;
- пагинация;
- manifest с `package_id`, `content_type`, `title`, `language`, `version`, `files`, `checksums`, `created_at`;
- SHA-256 каждого заявленного файла;
- защита от небезопасных путей;
- потоковая загрузка только файлов выбранного пакета без clone всего репозитория;
- ограничения временного диска и размера пакета;
- гарантированная очистка временных файлов;
- импорт книг и комиксов через существующий `import_library_zip`;
- история с package/version/commit SHA/status/размером/VoxLyra ID/ошибкой;
- повторный импорт уже успешно обработанного пакета не создаёт новую копию;
- новая версия определяется как обновление и требует явного действия владельца;
- массовый импорт всех новых книг и комиксов;
- повтор неудачных импортов;
- ошибка одного пакета не останавливает остальные;
- аудиокниги пока намеренно исключены из массового GitHub-импорта.

Подробный рабочий статус: `docs/GITHUB_IMPORT_V1_16_0_PROGRESS.md`.

### До merge в main

Нужно закончить усиленную дедупликацию, проверить сохранение покупок/прогресса/отзывов/рейтингов/закладок при обновлении, закрыть rollback и аварийные сценарии, выполнить полный набор тестов и устранить конфликт/причину `mergeable: false` у текущего PR.

Недопроверенная версия в `main` не сливается.

## Архитектурные правила

- Не переносить текущую SQLite БД с Bothost в рамках v1.16.0.
- Не переносить существующую библиотеку.
- Не создавать отдельное постоянное хранилище для GitHub-контента.
- Не заменять существующие способы импорта EPUB/FB2/TXT/PDF/CBZ/CBR/7Z/изображений и массовый импорт.
- Не хранить GitHub token в коде, UI, логах или traceback.
- Telegram и VK используют общую библиотеку и внутренний аккаунт, но платформенную оплату: Telegram Stars в Telegram и VK Votes в VK.
- Публикация произведения должна использовать платформенную ссылку: Telegram Mini App для Telegram и VK Mini App для VK.

## Основные каталоги

- `app/` — backend, Telegram/VK, сервисы, БД и бизнес-логика.
- `static/`, `templates/` — Mini App/web UI.
- `tests/` — автоматические тесты.
- `scripts/` — эксплуатационные и проверочные скрипты.
- `docs/` — актуальная техническая документация.
- `data/` — постоянные runtime-данные; реальные пользовательские данные не должны коммититься.
- `storage/` — временные/runtime-ресурсы в зависимости от текущей конфигурации.

## GitHub Import env

```env
GITHUB_IMPORT_ENABLED=false
GITHUB_IMPORT_REPOSITORY=Treninem/bookvoxlyra
GITHUB_IMPORT_BRANCH=main
GITHUB_IMPORT_ROOT=
GITHUB_IMPORT_TOKEN=
GITHUB_IMPORT_TEMP_ROOT=storage/github_import
GITHUB_IMPORT_MAX_PACKAGE_MB=2048
GITHUB_IMPORT_MIN_FREE_DISK_MB=256
GITHUB_IMPORT_PAGE_SIZE=50
```

Для публичного репозитория токен может не требоваться. Для приватного используется минимально необходимый read-only token через переменные окружения.

## Разработка и проверка

Перед merge необходимо выполнить тесты проекта и отдельные тесты GitHub-импорта. GitHub Actions для текущей feature-ветки на предыдущей проверке автоматически не запускались, поэтому отсутствие красного CI не считается подтверждением готовности.

## Чистота репозитория

Репозиторий постепенно очищается от старых автоматически созданных `CHANGED_FILES_*`, `FILE_INVENTORY_*`, временных release-отчётов и других файлов, которые не участвуют в работе приложения. Runtime-код, миграции, необходимые инструкции, тесты, юридические документы и актуальная эксплуатационная документация удаляться не должны.
